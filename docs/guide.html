Read and write

  • Python examples that write Images and Cubes, then read them back from local or remote storage.

These examples write an Image and a Cube, read part of a file back, run the same read against local and remote storage, and build training batches. The first four sections create data. If a catalog already gives you a source and its header, start at bands, times and windows. R and Julia have readers of their own, described in the R and Julia APIs.

Installation

Python writes files with Rumi and GeoZL, then reads them through the Rumi core. Installing rumi-eo also installs GeoZL. R and Julia read the files Python writes, with native readers.

python -m pip install rumi-eo
import geozl
import numpy as np
import rumi

Shapes and positions. In Python an Image is (B, Y, X) and a temporal Cube is (T, B, Y, X). Selections count from zero, and a window is (row, column, height, width). R and Julia count from one and return Images as (X, Y, Band) and Cubes as (X, Y, Band, Time).

One Image

This round trip stores a four-band Image in 256 × 256 spatial cells. Each frame holds all four bands of one cell.

image = np.random.default_rng(0).integers(
    0, 4096,
    size=(4, 1024, 1024),
    dtype=np.uint16,
)

frames = rumi.frames(
    image,
    "b (row h) (col w) -> row col (b h w)",
    tile_size=256,
)

for frame in frames:
    graph = geozl.graph(frame.data, "planar>zigzag>zstd")
    frame.compressed = geozl.compress(frame.data, graph=graph)

image_path, image_header = rumi.write(
    "image.rumi",
    frames,
    bands=[
        "B2, Blue, 496.6nm (S2A) / 492.1nm (S2B)",
        "B3, Green, 560nm (S2A) / 559nm (S2B)",
        "B4, Red, 664.5nm (S2A) / 665nm (S2B)",
        "B8, NIR, 835.1nm (S2A) / 833nm (S2B)",
    ],
    time=["2026-01-01"],
)
image_again = rumi.read(image_path, image_header)

image_path points at the stored file. image_header is the small external index to keep with it, in a catalog or a dataset manifest.

Every file names each band and dates each time step. bands takes one text per band, in band order. A good text gives the band name, a short description and the wavelength.

Every frame is explicit. rumi.frames returns decoded views of the frames. The loop builds a GeoZL graph for each frame and assigns its compressed payload. rumi.write refuses a table in which any frame has no payload.

Frame layouts

The logical Image does not change. Only the right side of the pattern changes, and with it how many samples are fetched and decoded together.

# One independently addressable frame per band and spatial tile.
tile_frames = rumi.frames(
    image,
    "b (row h) (col w) -> row col b (h w)",
    tile_size=256,
)

# One band-planar cell frame at each spatial position.
planar_cells = rumi.frames(
    image,
    "b (row h) (col w) -> row col (b h w)",
    tile_size=256,
)

# One pixel-interleaved cell frame at each spatial position.
chunky_cells = rumi.frames(
    image,
    "b (row h) (col w) -> row col (h w b)",
    tile_size=256,
)

A temporal Cube

This Cube has three time steps and four bands. Band and time sit outside each frame, so any one band at one step can be read without decoding the others.

cube = np.random.default_rng(1).integers(
    0, 4096,
    size=(3, 4, 1024, 1024),
    dtype=np.uint16,
)

cube_frames = rumi.frames(
    cube,
    "t b (row h) (col w) -> row col b t (h w)",
    tile_size=256,
)

for frame in cube_frames:
    graph = geozl.graph(frame.data, "planar>zigzag>zstd")
    frame.compressed = geozl.compress(frame.data, graph=graph)

cube_path, cube_header = rumi.write(
    "cube.rumi",
    cube_frames,
    bands=[
        "B2, Blue, 496.6nm (S2A) / 492.1nm (S2B)",
        "B3, Green, 560nm (S2A) / 559nm (S2B)",
        "B4, Red, 664.5nm (S2A) / 665nm (S2B)",
        "B8, NIR, 835.1nm (S2A) / 833nm (S2B)",
    ],
    time=["2026-01-01", "2026-02-01", "2026-03-01"],
)
tile framesrow col b t (h w) or row col t b (h w) keeps band and time separately addressable.
cell framesrow col (b t h w) lets one graph model the whole band and time block at each spatial position.

time takes dates, datetimes, ISO strings or NumPy datetime64 values, or one (start, end) interval per step. Its length must equal T.

Bands, times and windows

A list picks exact positions and may reorder them. A two-item tuple is a half-open range. The optional output pattern changes the order of the returned axes, not what is stored.

# Exact positions, time 2 and bands 3 then 1.
picked = rumi.read(
    cube_path,
    cube_header,
    time=[2],
    bands=[3, 1],
    window=(100, 200, 128, 128),
)

# Half-open ranges and a model-specific output order.
reordered = rumi.read(
    cube_path,
    cube_header,
    time=(0, 2),
    bands=(1, 4),
    window=(100, 200, 128, 128),
    pattern="t y x b",
)

time=[2] keeps exactly one step and keeps its time axis, so picked is (1, 2, 128, 128). bands=[3, 1] keeps two bands, in that order. window=(100, 200, 128, 128) returns 128 rows and 128 columns starting at row 100, column 200. With pattern="t y x b", reordered comes back as (2, 128, 128, 3).

Local and remote sources

This example runs as it is against the public Rumi fixtures. It reads the same bands and window from Source Cooperative, Hugging Face, the S3-compatible endpoint of Source Cooperative and a downloaded local file, then checks that all four results are identical.

import os
from pathlib import Path
from urllib.request import Request, urlopen

import numpy as np
import rumi

PRODUCT = "asterisk-labs/rumi-api-fixtures"
NAME = "s2-00-tile"
SOURCE_BASE = f"https://data.source.coop/{PRODUCT}"

def fetch(url):
    request = Request(url, headers={"User-Agent": "rumi-example"})
    with urlopen(request) as response:
        return response.read()

header = fetch(f"{SOURCE_BASE}/headers/{NAME}.header")
selection = dict(
    bands=[3, 0],
    window=(237, 233, 91, 107),
)

# Source Cooperative also serves an S3-compatible public endpoint.
os.environ["AWS_ENDPOINT_URL"] = "https://data.source.coop"
os.environ["AWS_NO_SIGN_REQUEST"] = "YES"
os.environ["AWS_VIRTUAL_HOSTING"] = "NO"

sources = {
    "Source Cooperative": f"source://{PRODUCT}/data/{NAME}.rumi",
    "Hugging Face": f"hf://datasets/{PRODUCT}@main/data/{NAME}.rumi",
    "S3": f"s3://asterisk-labs/rumi-api-fixtures/data/{NAME}.rumi",
}
chips = {
    label: np.asarray(rumi.read(uri, header, **selection))
    for label, uri in sources.items()
}

# Download once to run the same read from a local path.
local_dir = Path("rumi-api-fixtures")
local_dir.mkdir(exist_ok=True)
local_file = local_dir / f"{NAME}.rumi"
local_file.write_bytes(fetch(f"{SOURCE_BASE}/data/{NAME}.rumi"))
chips["Local"] = np.asarray(
    rumi.read(local_file, header, **selection)
)

reference = chips["Source Cooperative"]
assert reference.shape == (2, 91, 107)
assert all(np.array_equal(reference, chip) for chip in chips.values())

print({label: chip.shape for label, chip in chips.items()})

One object, four transports. The two mirrors hold byte-identical Rumi objects and headers. The S3 URI names the same Source Cooperative object as the source:// URI, and only the backend configuration changes. Remote reads send range requests, and the local read uses positional file reads.

Training batches

read_many plans all the items together and returns them along a leading n axis. Positions may differ, but every window must have the same height and width.

# Continue from the previous example.
names = ["s2-00-tile", "s2-01-tile", "s2-02-tile"]
headers = [
    fetch(f"{SOURCE_BASE}/headers/{name}.header")
    for name in names
]
sources = [
    f"source://{PRODUCT}/data/{names[0]}.rumi",
    f"hf://datasets/{PRODUCT}@main/data/{names[1]}.rumi",
    f"s3://asterisk-labs/rumi-api-fixtures/data/{names[2]}.rumi",
]
windows = [
    (0, 0, 128, 128),
    (128, 192, 128, 128),
    (320, 256, 128, 128),
]

batch = rumi.read_many(
    sources,
    headers,
    windows=windows,
    bands=[0, 1, 2, 3],
)

assert batch.shape == (3, 4, 128, 128)

Sources may mix local and remote storage. They must agree on tile size, dtype, band and time counts, and which axes their frames hold. The result keeps the input order even when ranges arrive in another order.

Why not a Python loop? A batch exposes the independent work of every item at once. Remote waits, local reads and OpenZL decoding then overlap while Rumi assembles one tensor of a known shape.

Frameworks and devices

Choose the destination in the read call. Results pass through DLPack with no NumPy copy in between. A device such as "cuda:0" or "mps" decodes straight into CUDA or Metal memory, for any framework but NumPy.

numpy_chip = rumi.read(cube_path, cube_header)
torch_chip = rumi.read(
    cube_path, cube_header, framework="torch"
)
jax_chip = rumi.read(
    cube_path, cube_header, framework="jax"
)
tensorflow_chip = rumi.read(
    cube_path, cube_header, framework="tensorflow"
)
dlpack_chip = rumi.read(
    cube_path, cube_header, framework="dlpack"
)
cuda_chip = rumi.read(
    cube_path, cube_header,
    framework="torch", device="cuda:0"
)
jax_cuda_chip = rumi.read(
    cube_path, cube_header,
    framework="jax", device="cuda:0"
)
mps_chip = rumi.read(
    cube_path, cube_header,
    framework="torch", device="mps"
)

framework sets what comes back.

"numpy"a NumPy array, the default
"torch"a PyTorch tensor
"jax"a JAX array. 64-bit dtypes need jax_enable_x64.
"tensorflow"a TensorFlow tensor
"dlpack"a RumiArray, a DLPack producer that exports once

Every Rumi dtype maps exactly to a CPU dtype that PyTorch accepts. NumPy, JAX and TensorFlow accept exact subsets. Rumi checks the dtype before it reads a frame, and it never casts or returns a byte view.

CUDA reads run on a stream Rumi owns. Importing the result makes the framework's current stream wait for the read on the device, without blocking the host. When the array is released, its memory returns to Rumi in that stream's order. Metal reads finish before they return.

Metadata and headers

A Rumi file describes itself. If the external header is missing, info rebuilds the canonical header, and it also returns the band texts, time and georeferencing stored in the file.

metadata = rumi.info(source="cube.rumi")
recovered_header = metadata.header

print(metadata.shape)         # (3, 4, 1024, 1024)
print(metadata.tile)          # (256, 256)
print(metadata.frame_layout)  # h w for the tile-frame Cube
print(metadata.bands)         # the four band texts
print(metadata.time)          # the three recorded dates

# Supplying both checks the header against the source.
checked = rumi.info(
    source="cube.rumi",
    header=recovered_header,
)
header onlyrumi.info(header=...) describes the read index without opening the source.
with a sourcerumi.info(source=...) also returns band texts, time coordinates, transform, CRS and a rebuilt header.
