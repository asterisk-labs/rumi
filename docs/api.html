A Rumi file is written once from frames that GeoZL has already compressed, and read many times by window, band and time step. Python writes and reads. C is the library every binding calls. R, Julia and JavaScript read. The examples run these calls end to end.

Write, then read

import geozl
import numpy as np
import rumi

image = np.random.default_rng(0).integers(0, 4096, (4, 1024, 1024), dtype=np.uint16)

frames = rumi.frames(image, "b (row h) (col w) -> row col (b h w)", tile_size=512)
for frame in frames:
    graph = geozl.graph(frame.data, "planar>zigzag>lanes")
    frame.compressed = geozl.compress(frame.data, graph=graph)

path, header = rumi.write("scene.rumi", frames, bands=["B2", "B3", "B4", "B8"],
                          time=["2024-08-25"])
chip = rumi.read(path, header, bands=[2, 3], window=(0, 0, 256, 256))

frames cuts the image into tiles, the loop compresses each one with GeoZL, and write stores the payloads as they are. write also returns the external header, a few dozen bytes that a reader needs before it opens the file. Keep it beside the path, in a catalog or a dataset index.

The same read can land on a GPU. With framework="torch" and device="cuda:0", or device="mps" on a Mac, GeoZL decodes the frames that end in PFOR or PivCo on the device and writes the samples straight into the tensor. Other frames decode on the CPU and are copied over.

Languages

PythonWrite and read, with windows, batches and GPU reads into PyTorch, JAX or TensorFlow. pip install rumi-eo
CThe library every binding calls, in rumi.h, with CPU, GPU and DLPack reads and the writer.
RA reader with one-based indices and native (X, Y, Band, Time) arrays.
JuliaA reader with one-based indices and native (X, Y, Band, Time) arrays.
JavaScriptA reader that opens a whole .rumi file and fetches only the byte ranges it needs. npm install @asterisk-labs/rumi

Python and JavaScript count from zero and return (Time, Band, Y, X). R and Julia count from one and return (X, Y, Band, Time), the order their arrays use.
